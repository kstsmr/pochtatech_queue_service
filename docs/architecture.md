# Архитектура, интеграции и масштабирование

## Фактически проверено в MVP

MVP запускается одним Docker Compose и содержит Nginx/React, stateless FastAPI,
PostgreSQL, Redis и отдельный notification worker. Состояние очереди, версии
правил, сессии, outbox и журналы находятся в PostgreSQL. Redis используется как
распределённый rate limiter и задел под межпроцессные сигналы; корректность
вызова не зависит от блокировки в памяти и обеспечивается транзакциями PostgreSQL.

Локальными smoke-тестами проверяются три входа, конкурентная идемпотентность,
одновременный вызов двумя окнами, закрытие с активным клиентом, перенаправление,
панели оператора и руководителя, WebSocket и доставка demo-уведомления.

## Внешние системы и направления обмена

| Система | Направление | Назначение в MVP | Производственная замена |
|---|---|---|---|
| Мобильное приложение Почты | вход в E-СУО | защищённый demo endpoint предзаписи | реальный контракт МП/шина событий |
| Сервис уведомлений | выход из E-СУО | adapter `log/unavailable/timeout` | push, SMS или корпоративный шлюз |
| Учётная система сотрудников | вход в E-СУО | demo-сотрудники и PIN hash | SSO/учётная запись ПочтаТех |
| Справочник ОПС и графиков | вход в E-СУО | seed пяти отделений | официальный мастер-справочник |

Интеграционные endpoint-ы и адаптеры не содержат алгоритм очереди. Поэтому замена
demo-компонента не меняет транзакции талона, приоритет или рабочее место оператора.

## Расчётный контур для 40 000 отделений

Следующие числа являются предположениями для проектирования, а не результатом
нагрузочного теста MVP. При 250 талонах на отделение в день сеть создаёт около
10 млн талонов в сутки. Если 15% дневного потока приходится на пиковый час, это
примерно 420 созданий талона в секунду по сети; чтения статуса и WebSocket дают
на порядок больший поток. Плановый запас должен составлять минимум 3-5 раз.

Предлагаемая схема:

1. Отделения закрепляются за региональными ячейками по стабильному `branch_id`.
   Ячейка содержит API, PostgreSQL-кластер, Redis и workers и обслуживает только
   свой диапазон отделений.
2. Внутри PostgreSQL таблицы талонов, событий и outbox партиционируются сначала
   по региону/хэшу отделения, затем по времени. Все ключевые индексы начинаются
   с `branch_id`; сбой одной ячейки не останавливает остальные регионы.
3. API и workers горизонтально масштабируются. Единственное решение о вызове
   остаётся в БД через row lock и `SKIP LOCKED`, поэтому несколько экземпляров
   не назначают талон дважды.
4. Центральный control plane хранит версии правил и справочников. Ячейки получают
   подписанные версии, применяют их атомарно и продолжают работать на последней
   подтверждённой версии при потере связи с центром.
5. Аналитические события передаются асинхронно в отдельное хранилище. Дашборд
   конкретного отделения читает оперативную БД; тяжёлые сетевые отчёты не влияют
   на вызов клиентов.
6. Справочник отделений запрашивается страницами и через серверный поиск по
   индексу, названию или адресу. Клиент не загружает каталог из 40 000 записей.

## Проблемы связи

- Клиент хранит ID и непрозрачный токен талона на устройстве, использует REST
  fallback и восстанавливает WebSocket после связи.
- Notification outbox переживает недоступность шлюза и повторяет доставку.
- При потере связи отделения с центральным control plane региональная ячейка
  продолжает использовать последнюю версию правил.
- Полностью автономная работа оператора без связи с региональной ячейкой в MVP
  не реализована. Для промышленного режима потребуется локальный edge-узел с
  журналом команд и последующим разрешением конфликтов; это отдельный этап, а не
  заявленный результат текущей проверки.

## Российский технологический контур

Python/FastAPI, PostgreSQL, Redis-compatible storage, React, Nginx и OCI-контейнеры
являются переносимыми open-source компонентами и не требуют зарубежного SaaS.
Образы можно собирать во внутреннем registry и размещать на российской ОС и
инфраструктуре. Перед промышленным внедрением конкретные версии и registry должны
пройти проверку по утверждённому заказчиком перечню, которого в материалах задачи
нет.
