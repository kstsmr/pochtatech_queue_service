# Талон: поля и переходы v1

## Поля

| Поле | Смысл |
| --- | --- |
| id / branch_id / service_id | UUID талона, отделение и текущая услуга |
| ticket_number | Уникальный BIGINT identity, публичный номер |
| queue_sequence | BIGINT identity: стабильный FIFO, сохраняется при возврате |
| source | prebooking / qr / walk_in; не меняется при перенаправлении |
| status | booked / waiting / called / serving / served / no_show / cancelled |
| window_id | Только фактическое назначение в called/serving |
| target_window_id | Ограничение выбора после перенаправления; не назначение |
| slot_id / scheduled_time | Исходная запись, обязательны только для prebooking |
| eligible_at | Момент начала участия в очереди |
| priority_level | Вычисляемый ответ API по правилам и текущему времени, не постоянная колонка |
| session_id | Владелец талона; nullable только для walk_in |
| created_at / updated_at | Серверное время создания и последней мутации |
| called_at / service_started_at | Последний вызов и начало текущего обслуживания |
| closed_at | Только терминальное состояние |
| version | Увеличивается ровно на 1 при каждой мутации; событие той же версии |
| return_count / redirect_count | Счётчики соответствующих действий |

Историю прежних вызовов, окон и интервалов сохраняет ticket_events. Исходное
время записи сохраняется, даже если после перенаправления слот отсоединён.

## Переходы

| Действие | Откуда | Куда | Условия |
| --- | --- | --- | --- |
| prebooking | — | booked | Есть свободное место в слоте |
| qr / walk_in | — | waiting | Услуга доступна; walk_in создаёт оператор |
| activate | booked | waiting | now >= eligible_at, идемпотентно |
| call | waiting | called | Открытое свободное совместимое окно |
| start | called | serving | Подтверждение оператора о начале обслуживания |
| complete | serving | served | Освободить окно, закрыть талон |
| return | called / serving | waiting | Снять назначение, сохранить FIFO, записать причину |
| redirect | called / serving | waiting | Проверить услугу и целевое окно того же отделения |
| cancel | booked / waiting / called | cancelled | Действующий владелец или уполномоченный сотрудник |
| no_show | called | no_show | Истёк call timeout, оператор подтвердил неявку |

served/no_show/cancelled терминальны. Повтор с тем же Idempotency-Key возвращает
прежний ответ; новая несовместимая команда получает 409. Отмена во время serving
запрещена: клиент уже у оператора. Все изменения проходят общий lock-протокол.

returned/redirected из исходного плана представлены action в event log,
а не отдельными состояниями, иначе такие талоны легко потерять из waiting-выборки.
booked добавлен, чтобы будущие записи не попадали в текущую очередь.
Фоновая активация и call-next оба обрабатывают наступившие booked под блокировкой;
после restart обязательна проверка просроченных активаций из БД.

## Закрытие и перенаправление

Обычное закрытие свободного окна: closed. С called: возврат талона в waiting
и закрытие одной транзакцией. С serving: draining, новые вызовы запрещены,
текущее обслуживание завершается, затем closed. Принудительное закрытие с serving
требует явной команды оператора и причины; возвращает талон в waiting и пишет
событие прерывания. Обычное закрытие не прерывает уже выполняемую операцию.

Перенаправление не назначает клиента в занятое окно: target_window_id ограничивает
последующий выбор. Целевое окно должно быть open и поддерживать услугу.
При его закрытии снять target_window_id со всех ожидающих талонов в той же
транзакции, записать событие каждому; иначе клиент зависнет навсегда.
Менять услуги окна с активным клиентом несовместимым образом запрещено.

При redirect меняется service_id, slot_id освобождается/отсоединяется, если был,
scheduled_time остаётся историческим. Новый уровень определяется общими правилами
без повторного бонуса записи (redirect_count > 0), исходный FIFO сохраняется.
Если нет ни одного подходящего окна, талон остаётся waiting; ETA = null с причиной,
руководитель видит отклонение. Число минут не придумывается.

## Допущение о присутствии

В MVP предзапись активируется автоматически: дополнительный check-in не требуется.
Вызов возможен с начала early_minutes. Неявка фиксируется только после фактического
вызова, не потому что отделение само задержало обслуживание. После grace_minutes
бонус записи заканчивается, но клиент остаётся в очереди.
